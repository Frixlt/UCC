# Правила агента для репозитория UCC-Revorked

## 1. Git и обязательные атомарные коммиты
- **Каждое завершённое логическое изменение** (исправление, новая фича, этап рефакторинга, набор тестов или обновление документации) **должно быть закоммичено сразу после прохождения проверок**. Не накапливай незакоммиченную работу в рабочем дереве.
- Делай **атомарные логические коммиты** с понятными conventional-сообщениями (`fix(...)`, `feat(...)`, `test(...)`, `chore(...)`, `docs(...)`).
- Перед коммитом обязательно проверяй `git status --short` и `git diff --cached --stat`, чтобы не захватить сборочные артефакты, скомпилированные ELF/`.so` бинарники, логи или временные файлы.
- Никогда не выполняй `git push` и деструктивные операции с историей (`git reset --hard`, `git push --force`) без явного запроса пользователя.

## 2. Инструментарий и обязательная проверка перед коммитом
- В неинтерактивной оболочке Rust toolchain может отсутствовать в `PATH`: всегда предваряй команды `export PATH="$HOME/.cargo/bin:$PATH"`.
- Перед любым коммитом с изменениями Rust-кода запускай:
  - `cargo clippy --workspace --all-targets --locked --offline -- -D warnings`
  - `cargo test --workspace --locked --offline`

## 3. Тестовые фикстуры и чистота репозитория
- **Запрещено** ссылаться в автотестах на игнорируемый каталог `artifacts/` или прописывать машинно-зависимые абсолютные пути (например `/home/frixit/...`). Все фикстуры тестов должны отслеживаться в Git (например в `crates/*/tests/fixtures/` или `stand-fixtures/`).
- **Запрещено** оставлять в репозитории временные `_tmp_*` тест-файлы, отладочные `.so`/ELF-бинарники и временные каталоги сборки.

## 4. Доступ к root
- Соблюдай глобальное правило: для команд, запускаемых агентом через инструменты, использовать **`pkexec`**; в текстовых инструкциях пользователю — **`sudo`**.
