# Перенос личного ControlCenter в Frixit Control Center

Состояние: 0.3.0, 22 октября 2026 года. Форк установлен и запущен на основной
Mechrevo-машине; старые Python/TCC-контроллеры остановлены. Это уже выполненный
перенос, а не только план. [Основной README](../../README.md),
[сравнение](../../docs/COMPARISON.md), [проверки](../../docs/TESTING.md).

Исходники Python сохранены в [Frixlt/ControlCenter-Python](https://github.com/Frixlt/ControlCenter-Python),
тег `python-archive-2026-10-22`. Архив имеет собственные Apache-2.0/NOTICE.
Нативная интеграция остаётся GPL-3.0-or-later с авторством Frixit и upstream.
[Коммиты-источники](../../PROJECT_ORIGINS.md).

## Что перенесено

- Политики CPU/устройств AC / Type-C / Battery, ручные режимы и запросы приложений.
- Governor, EPP, turbo, ASPM, PCI/USB runtime PM, Wi-Fi и поддерживаемые
  системные/служебные параметры. Сканирование сохраняет отсутствующие устройства.
- Физические LED ID и личная раскладка: Enter 56, LShift 21, LCtrl 0;
  101 физическая клавиша при 126 обнаруженных зонах на проверенном устройстве.
- RGB/яркость, мультивыделение и сохранение состояния клавиатуры.
- Lightbar по режимам питания, пять анимаций, Silent/Welcome/Test. Flash
  выключен между событиями, сразу после Save, смены питания и запуска.
- Самостоятельный Qt-трей, батарея в ваттах и пользовательские NVIDIA-процессы.
- Предложения частоты экрана KDE по реальным KScreen mode ID с подтверждением
  через действие уведомления и сохранением разрешения.
- Агент уведомлений без передачи текста уведомлений в системный демон.
- Диагностика драйверов: login notification и красная плашка Overview.
- Активация GUI из трея с Wayland-токеном и переходом на рабочий стол окна.

`gpu-run` и старая CPU thermal/MSR-реализация исключены по запросу владельца.
Исходные пользовательские TDP/cTGP-настройки сохраняются при импорте, но не
публикуются как рекомендуемые дефолты.

## Приоритеты и режимы

Физический источник питания, эффективный режим и выбранный профиль — отдельные
состояния. Ручной режим выигрывает у автоматического. D-Bus-запросы приложений
могут повышать эффективный режим и исчезают при закрытии соединения.
Старые настройки без Type-C profile assignment используют AC как fallback.

Включённая per-mode политика CPU имеет приоритет над CPU-настройками профиля.
Устройства получают выбранную колонку и при активном профиле водянки.
Отключение политики не восстанавливает автоматически все ранее записанные
значения устройств; сначала примените желаемую колонку или измените параметры.
NVIDIA D0/persistence workaround, если включён, имеет приоритет над runtime PM auto.

## Offline import

`migrate-controlcenter.py` читает исходную папку Data и создаёт новый private
каталог. Он не устанавливает настройки, не меняет службы и не управляет железом.
Нужны актуальные `config.json`, `keyboard_colors.json`, `lightbar.json` и
`gui_settings.json`; старый rgb-config не заменяет текущие цвета.

```bash
ucc-cli --json keyboard info > capabilities.json
ucc-cli --json statemap get > baseline-settings.json
python3 contrib/frixit/migrate-controlcenter.py \
  /path/to/ControlCenter/Data ./new-import \
  --capabilities capabilities.json --settings baseline-settings.json
```

Либо разрешите ссылки на исходные TCC-профили из установленного TCC:

```bash
python3 contrib/frixit/migrate-controlcenter.py \
  /path/to/ControlCenter/Data ./new-import \
  --capabilities capabilities.json \
  --tcc-dir /etc/tcc \
  --tcc-archive /opt/tuxedo-control-center/resources/app.asar
```

Архив app.asar читается ограниченным парсером статических fan presets:
JavaScript не запускается. Отсутствующие профили/неверные данные отклоняются;
кривые и значения мощности не угадываются. Named presets учитывают исходные
min/max/offset; custom curves используют исходное округление. Параметры водянки
из явно переданных UCC-настроек имеют приоритет при конфликте профилей.

Результат: `settings`, `report.json`, `pending.json`, `desktop-preferences.json`.
В отчёте перечислены количества/исключения/неразрешённые профили. Тема и
start-minimized импортируются отдельно от аппаратных настроек.
Выполненный локальный импорт сохранил 57 политик устройств, 101 клавишу и
три разрешённых профиля. Личные выходные файлы хранятся только локально.

## Кривые max performance

[fan-max-performance-85.json](fan-max-performance-85.json) содержит только
монотонные CPU/GPU-кривые, достигающие 100% при 85 °C. Мощность и водянка
этим пресетом не изменяются. При `sameSpeed` оба вентилятора используют большую
рассчитанную скорость. Runtime-фильтрация/гистерезис/защита backend сохраняются.
Это не температурный лимит CPU. Для сохранения нужны custom fan profile и
ссылающийся на него performance profile; временное применение не равно сохранению.

## Службы, драйверы и восстановление

Первоначальный переход с резервированием и откатом:
[DEPLOYMENT.md](DEPLOYMENT.md). Не запускайте first-install скрипт поверх
существующего UCC. Общая установка/обновление: [BUILDING.md](../../docs/BUILDING.md).

На Linux 7.3 восстановлены DKMS, ITE-клавиатура и Lightbar; совместимый патч,
исходный driver commit и исправление локального updater:
[drivers/README.md](drivers/README.md). Диагностика драйвера работает отдельно
от проверки соединения с D-Bus-службой. Её проверки read-only.

Трей и session agent устанавливаются в XDG-autostart. Повторный запуск GUI
активирует один экземпляр; явный tray click игнорирует start-minimized,
автоматический запуск его учитывает. Пользователь подтвердил переход на рабочий
стол окна по клику в KDE Wayland.

Общий sleep hook сохраняет ручной режим и enable-состояние водянки, затем
останавливает/восстанавливает демон. Настоящий аппаратный suspend/resume ещё
не подтверждён. Известный полный GUI-audit timeout описан в актуальном
[отчёте о проверках](../../docs/TESTING.md); локальные журналы и deployment
exceptions не публикуются как полностью успешный аудит.
