# Справочник EC-регистров и протоколов Uniwill `0x1A` (`IDY_7Y` / `X6AR55xY`)

**Целевая верифицированная платформа:** MECHREVO YAOSHI Series-X6AR55xY (`project_id = 0x1A` = `13 << 1` = `IDY_7Y`), Intel Core Ultra 9 275HX (Arrow Lake-HX) + NVIDIA GeForce RTX 5080 Laptop GPU (150 W base / 175 W max TGP).

- Живые замеры через `/dev/uwcc` (`uwcc-rs`) на `YAOSHI Series-X6AR55xY` (2026-11-28).
- Официальный драйвер ядра Linux: [`drivers/platform/x86/uniwill/uniwill-acpi.c`](https://raw.githubusercontent.com/torvalds/linux/master/drivers/platform/x86/uniwill/uniwill-acpi.c).
- Спецификация и профили [`open-uniwill-cc`](https://github.com/aspidovss/open-uniwill-cc/blob/main/docs/EC/Registers.ru.md) и [`Platforms.ru.md`](https://github.com/aspidovss/open-uniwill-cc/blob/main/docs/EC/Platforms.ru.md).
- Профиль платы `IDY_7Y` / `X6AR55xY` из [`MechControl-RE`](https://github.com/Liddo-kun/MechControl-RE/blob/main/Profiles/MECHREVO/IDY_7Y.json).

## 2. Логика режимов питания (`PMSC`) и разгадка лимита 45 Вт

На платах проекта `0x1A` (MECHREVO Yaoshi `X6AR55xY`, Aurora X, XMG NEO 16 E25) метод DSDT **`PMSC`** определяет активный режим питания в строгом порядке приоритета:

1. **`0x0727` `BIT(6)` (`CUME = 0x40`) == 1** *(вместе с `0x0726` `BIT(7)` = `0x80`)* → **Custom** (индикатор кнопки режима загорается **белым**; EC начинает применять пользовательские `0x0783..0x0785` PL1/PL2/PL4 и пользовательские таблицы вентиляторов).
2. иначе **`0x0751` `BIT(4)` (`TBME` / `FAN_MODE_TURBO = 0x10`) == 1** → **Turbo / Игровой** (на `X6AR55xY` GPU до ~149–175 Вт, но в кросс-нагрузке CPU зажат внутренним лимитом EC ~45 Вт).
3. иначе **`0x0751` `BIT(7)` (`UFME` / `FAN_MODE_USER = 0x80`) == 1** → **Office** (CPU жёстко ограничен **45 Вт `[PL2]`**, GPU ~107 Вт!).
4. иначе (`0x0751 = 0x00`) → **Gaming** (заводские лимиты).

### Таблица регистров режимов

| Регистр | Биты / значения | Назначение |
| --- | --- | --- |
| `0x0726` | `BIT(7)` (`0x80`) | Флаг режима **Custom** (контур управления питанием). `BIT(3)` — включение от сети, `BIT(4..5)` — защита, `BIT(6)` — тепловая защита. Писать только через RMW! |
| `0x0727` | `BIT(6)` (`0x40`) | **`CUME`** — включение режима **Custom** в прошивке `0x1A`. **ВНИМАНИЕ:** `BIT(7)` — это `PL4D` (отключение PL4), **никогда не изменять `BIT(7)`!** |
| `0x0751` | `BIT(0..2)` (`0x07`)<br>`BIT(4)` (`0x10`)<br>`BIT(5)` (`0x20`)<br>`BIT(6)` (`0x40`)<br>`BIT(7)` (`0x80`) | `EC_ADDR_MANUAL_FAN_CTRL`:<br>• `FAN_LEVEL_MASK` (`GENMASK(2, 0)`)<br>• `FAN_MODE_TURBO` (`TBME`) — Игровой / Turbo<br>• `FAN_MODE_HIGH` — в комбинации `0xA0` (`0x80 \| 0x20`) включает Office (зелёный индикатор, подтверждено вживую)<br>• `FAN_MODE_BOOST` — оба вентилятора на максимум<br>• `FAN_MODE_USER` (`UFME`) — **без `CUME` трактуется как Office (45 Вт)!** С активным `CUME` (`0x0727` `BIT(6)`) + `0x07C6` `BIT(2)` включает пользовательский режим Custom без отката в Office. |
| `0x0752` | R (`0x6C` на `X6AR55xY`) | **НЕ является индексом профиля `1..=3` на `0x1A`!** Не перезаписывать произвольно. |
| `0x0753` / `0x0754` | R/W | **НЕ является `MODE_ENABLE` на `0x1A`!** По данным `MechControl-RE`, это предел тока VRM CPU / максимальный предел тока. |

### Почему раньше CPU упирался в 45 Вт (даже при `intel-rapl = 210 W`)

1. На Core Ultra 9 275HX итоговый предел мощности равен `min(MSR RAPL, MMIO RAPL, EC PECI)`.
2. `uccd` записывал `210 W` в `intel-rapl`, но:
   - не выставлял `0x0741` `BIT(0)` (`ENABLE_MANUAL_CTRL`), из-за чего EC сбрасывал `0x0783..0x0785` обратно в `0` за 1 секунду;
   - выставлял `0x0751 |= 0x80` (`UFME`) для ручного управления вентиляторами **без `0x0726` `BIT(7)` и `0x0727` `BIT(6)` (`CUME`)**, из-за чего `PMSC` на `0x1A` переводил ноутбук в **Office (45 Вт)**!
3. При включении `0x0726 |= 0x80` + `0x0727 |= 0x40` (`CUME`) + `0x0741 |= 0x01` + `0x0751 = 0x80` (+ `0x07C6 |= 0x04`) активируется **Custom (белая лампочка)** и EC применяет заданные `0x0783..0x0785`.

## 4. Мощность GPU (NVIDIA cTGP / Dynamic Boost) и MUX

| Регистр | Доступ | Описание |
| --- | :---: | --- |
| `0x0743` | R/W | `TGP_DB_Control` (`mask 0x07`): `BIT(0)` — функция Dynamic Boost, `BIT(1)` — DB включён, `BIT(2)` — функция cTGP. |
| `0x0744` | R/W | `ConfigurableTGP`: смещение cTGP сверх базового (Вт; на `X6AR55xY` при `PWBT`/cTGP читалось `175`). |

**Методы ACPI (`INOU0000`):**
- `SMRW({0xBB, key})` — заводская таблица пределов Smart APC (12 байт на `INOU0000`).
- `PWUP(level)` — уровень мощности при СЖО (`0..=5`, управляет базовым лимитом NVIDIA `NPCF`: `150 W → 175 W`).
- `PWBT` / `PWDB` — прямое управление базовым TGP и Dynamic Boost через `NPCF`.
- `MXDS` / `MXDM` — чтение и переключение режима MUX при загрузке (`hybrid` / `dgpu_only` / `igpu_only`).

## 6. Батарея, переключатели, СЖО и подсветка

### Батарея (взаимоисключающие механизмы)
- **Пороги заряда:** `0x07B9` (`BIT(0..6)` = верхний порог %, `0` = 100%, `BIT(7)` = `CHARGE_CTRL_REACHED` — не перезаписывать!), `0x07D0` (нижний порог `1..=95%`).
- **Режимы защиты (`X6AR55xY`):** `0x07A6` (`mask 0x38` / `BIT(4..5)`): `0x08` = High Capacity, `0x18` = Balanced, `0x28` = Stationary.
- **Телеметрия батареи (R):** `0x0402..0x0403` (design mAh), `0x0404..0x0405` (full charge mAh), `0x0436..0x0437` (remaining mAh), `0x0438..0x0439` (mV), `0x04A2..0x04A3` (temp `0.1 K`), `0x04AB` (SoC %).

### Переключатели
- `0x074E` `BIT(4)` — Fn Lock (R/W).
- `0x0767` (триггер) / `0x0768` (статус): `BIT(0)` Win Lock, `BIT(1)` Lightbar, `BIT(2)` Fan Boost, `BIT(4)` USB Sleep Charging, `BIT(5)` RGB Apply Color.
- `0x07A6` `BIT(3)` — индикатор тачпада, `BIT(6)` — переключатель тачпада выключен.

### Водяное охлаждение (СЖО)
- `0x07A4` `BIT(7)` — поддержка СЖО; `0x07C8` `BIT(5)` — публикация целей EC.
- `0x07C7`: `BIT(1)` — СЖО подключена (ставит демон), `BIT(2..4)` — выбранный EC уровень мощности (передаётся в `PWUP(level)`).
- `0x07E6` (цель вентилятора СЖО, `BIT(7)` valid), `0x07E7` (цель помпы, `BIT(7)` valid).

### Подсветка (ITE HID + EC persistence)
- **Клавиатура и передняя полоса:** ITE HID (`048D:600B` клавиатура, `048D:7001` 4-зонная полоса, `048D:7000` 6-зонная).
- **AC-флаг полосы:** `0x0748` `BIT(0)` (`LIGHTBAR_APP_EXISTS`).
- **Логотип крышки (`X6AR55xY`):** физический свет меняется HID-командой Zone 3, а EC хранит состояние для восстановления после сна/перезагрузки: `0x0769..=0x076B` (`R/G/B` `0..=50`), `0x07AB` (`0x01` off / `0x21` low / `0x41` med / `0x81` high, `BIT(0)` = logo exists), `0x078C = 0x10` (commit), `0x07C5` `BIT(5)`.

## 7. Физическая кнопка смены режима, WMI `0x00B0` и будущее переназначение

Поведение физической кнопки смены режима питания на корпусе напрямую управляется битом `0x0741` `BIT(0)` (`EC_ADDR_AP_OEM` / `AP_EXIST`, подтверждено вживую на `X6AR55xY`):

| Состояние `0x0741` `BIT(0)` | Поведение кнопки на корпусе | WMI-событие | Назначение |
| :---: | --- | :---: | --- |
| `0` (например `0x80`) | Автономный режим EC: кнопка напрямую циклически переключает аппаратные режимы `Office / Gaming / Turbo` в прошивке (подтверждено вживую). | Не перехватывается хостом | Штатная работа без демона / чистый возврат управления EC при остановке `uccd`. |
| `1` (например `0x81`) | Режим хост-управления (`AP_EXIST`): EC передаёт нажатие в ОС через WMI-событие **`0x00B0`**. | `0x00B0` (`UNIWILL_OSD_PERFORMANCE_MODE_TOGGLE` в upstream `uniwill-acpi.c`, `KEY_F14`) | Позволяет `uccd` полностью перехватывать и **переназначать** кнопку на любое действие. |

### Найденный баг (причина переключения тачпада)
- В `crates/ucc-hardware/src/uwcc/wmi_events.rs:27` код `0x00B0` был ошибочно замаплен на `TOUCHPAD_TOGGLE` (`KEY_TOUCHPAD_TOGGLE = 530`) вместо `PERF_MODE_CYCLE`.
- Как только мы выставили `0x0741 |= 0x01` (`0x81`), EC переключил кнопку режима на генерацию `0x00B0`, и `uccd` начал превращать её нажатия в `KEY_TOUCHPAD_TOGGLE`.
- Возврат `0x0741 = 0x80` мгновенно вернул кнопке штатное поведение EC.

### Задел на переназначение кнопки в UCC (будущая фича)
Поскольку при активном `uccd` бит `0x0741` `BIT(0)` всё равно включён (он нужен для удержания `0x0783..0x0785`), событие `0x00B0` поступает напрямую в обработчик WMI-событий `uccd`. Это позволяет в дальнейшем добавить настройку действия кнопки режима в GUI/конфиге:
- **Циклическое переключение профилей UCC** (включая пользовательский `Custom` с белой лампой, который аппаратная кнопка сама по себе выбрать не умеет).
- **Быстрое переключение на закреплённый профиль** (например, `Silent ↔ Custom Max` или `Turbo`).
- **Переназначение на произвольную клавишу / шорткат** через `uinput` (по умолчанию `KEY_F14`, как в upstream `uniwill-acpi.c`, или отключение `uinput`-эмиссии, если действие обрабатывает сам `uccd`).
- **Обязательный cleanup при остановке `uccd`:** сбрасывать `0x0741 &= ~0x01` (RMW), чтобы при выключенном демоне кнопка гарантированно возвращалась в автономный режим EC.

## 8. План исправлений в коде UCC по итогам исследования

3. **`crates/ucc-hardware/src/uwcc/mod.rs`:**
   - убрать ошибочную запись `0x0753` в `set_mode_enable()` (на `0x1A` `0x0753` — это VRM current limit, а не `MODE_ENABLE`);
   - реализовать честное переключение режимов `0x1A` (`Custom` = `0x0726 |= 0x80` + `0x0727 |= 0x40` без затирания `BIT(7)` + `0x0741 |= 0x01` + `0x0751 = 0x80` + `0x07C6 |= 0x04`, `Turbo` = `0x0751 = 0x10` со снятием `CUME`, `Office` = `0x0751 = 0xA0`, `Gaming` = `0x0751 = 0x00`);

   - при завершении работы `uccd` сбрасывать `0x0741` `BIT(0)` обратно в `0` (RMW), возвращая кнопку режимов под управление EC.
4. **Dashboard (`M16.05`):** выводить живые лимиты из EC (`PL1/PL2/PL4`, `cTGP`, активный аппаратный режим `PMSC`: `Office / Gaming / Turbo / Custom`) в карточках CPU/GPU.

## 9. Живые замеры на `X6AR55xY` (2026-11-28)

- **Активация Custom (`CUME` + `0x0726 BIT(7)` + `0x0741 BIT(0)`):** сняла потолок 45 Вт — CPU вышел на **117+ Вт** под нагрузкой.
- **Рукопожатие активации `0x0741`:** запись `0x0741 |= 0x05` (`BIT(0) | BIT(2)`) подтверждается EC сбросом `BIT(2)` (`0x85 → 0x81`).
- **`0x0706` (`CUSTOM_MODE`):** заводское состояние `0x40`, в `MechControl-RE` активируется записью `0x41` (`BIT(0)`).
