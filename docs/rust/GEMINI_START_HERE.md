# Комплект задания для Gemini: полный перенос Control Center на Rust

Этот комплект превращает [архитектурный план](MIGRATION_PLAN.md) в инструкции для длительной работы с четырьмя ролями: **W1 и W2 реализуют, R1 и R2 независимо проверяют и тестируют**. Создание этого комплекта не означает, что агенты уже запущены или реализация начата.

## Как передать задание

Открыть в агентном приложении Gemini репозиторий `UCC-Revorked`, дать доступ к чтению/редактированию файлов и запуску команд. Основной текст для вставки целиком: **[GEMINI_MASTER_PROMPT.md](GEMINI_MASTER_PROMPT.md)**. Если модель видит репозиторий, достаточно вставить краткий запуск ниже; если доступа к файлам нет, сначала нужно предоставить файлы комплекта, иначе выполнить работу она не сможет.

```text
Твоя задача — выполнить полный перенос Frixit Control Center на Rust.
Сначала полностью прочитай docs/rust/GEMINI_MASTER_PROMPT.md и все обязательные
документы из его списка. Это исполняемое техническое задание.
Организуй четыре реальные рабочие роли: W1/W2 — реализация, R1/R2 — независимое
ревью и тесты. Соблюдай лимит среды; координатор не должен стать пятым воркером.
Начни с проверки сохранённой базы и волны V0 из GEMINI_EXECUTION_PLAYBOOK.md.
Создай отслеживаемое состояние задач и реальные test/evidence registries.
Затем выполняй доступные задачи по зависимостям до полного результата.
Все F01–F44, 122 D-Bus-метода, 7 сигналов, 10 страниц и остальные сценарии
должны быть покрыты проверками. Не подменяй работающие функции заглушками.
Не объявляй успех по количеству файлов или тестов. Закрывай задачу только после
независимого R1-ревью и R2-проверки точного интеграционного commit.
```

## Что требуется от среды

- Реальные инструменты создания/сообщений/ожидания агентов либо понятный интерфейс параллельных задач. Имена конкретных API заранее не выдуманы.
- Shell, Git, Rust toolchain и зависимости для обычной сборки; необходимые недостающие зависимости выявляются и учитываются отдельно.
- Изолированный D-Bus и fake sysfs/procfs для большинства тестов. Обычные тесты не требуют root или live hardware.
- Для заключительных аппаратных сценариев нужны реальный ноутбук и рабочая сессия. Недоступный сценарий остаётся `hardware_pending`.

Если среда не поддерживает агентов, текст промпта не создаст такую поддержку. Модель должна назвать ограничение, не писать вымышленные отчёты четырёх агентов и продолжить независимую подготовку. Последовательное исполнение четырёх ролей обозначается как fallback и не выдаётся за четыре одновременных потока.

## Границы результата

Конечный результат — работающий центр, проверенные пакеты, миграция и откат. Полнота тестов означает покрытие всех требований и значимых сценариев, а не математическое доказательство отсутствия ошибок. Непроверенный настоящий сон, BLE reconnect или compositor activation нельзя закрыть unit-тестом fake backend.

План не даёт права удалять функциональность GNOME/Plasma молча. Строгий Rust-only runtime и обязательное встраивание в GJS/QML оболочки требуют отдельного зафиксированного решения, описанного в основном плане. Пока оно не принято, сохранять старые shell-компоненты и выполнять независимые этапы.
