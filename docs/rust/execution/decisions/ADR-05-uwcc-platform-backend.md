# ADR-05: Переход на собственный Rust `uwcc` backend и абстракция `PlatformBackend` (`M14`)

## Статус
Принято (Accepted) — целевой этап `M14` после завершения базовой миграции Rust-сервиса (`M0–M13`), при этом архитектурные швы закладываются заранее на этапах `M4`, `M6` и `M8`.

## Контекст
1. Текущая зависимость от внешнего `tuxedo-drivers-dkms` (`tuxedo_io`, `uniwill_wmi`, `tuxedo_keyboard`, `tuxedo_nb02_nvidia_power_ctrl`, `ite_8291`, `ite_8291_lb`) хрупкая на новых ядрах Linux (уже требуется локальный патч под Linux 7.3) и не даёт доступа к ряду возможностей шасси `0x1A`:
   - чтению заводской таблицы пределов `SMRW`;
   - ограничению температуры CPU (`TCC offset`) и целевой температуре GPU;
   - повышению мощности при работе СЖО (`PWUP`);
   - нативным 16-точечным кривым `RamFan 1.5` в ОЗУ EC (`0xF00–0xF5C` с флагами `CUME`/`UFME`);
   - чтению реальных оборотов тахометра вентиляторов (RPM: EC `0x464/0x465` CPU, `0x46C/0x46B` GPU, скважность `0x75B/0x75C`) и экспорту нативного `/sys/class/hwmon/hwmonX`;
   - управлению зонами подсветки корпуса и логотипа на крышке (`048D:7001`/`048D:7000` и EC-выключатель полосы `0x767`/`0x768`);
   - отключению встроенной камеры (комбинированная USB RGB+IR UVC-камера на шине USB для Uniwill без Clevo `W_CL_WEBCAM_SW`).
2. На целевой машине (`MECHREVO YAOSHI Series-X6AR55xY`, проект `0x1A`) подтверждены:
   - наличие ACPI-устройства `/sys/bus/acpi/devices/INOU0000:00`;
   - поддержка Rust в ядре CachyOS Linux 7.3 (`CONFIG_RUST=y`, `CONFIG_ACPI_WMI=m`, `rustc 1.100.0`).
3. Открытый проект `open-uniwill-cc` задокументировал и проверил протокол EC/ACPI для `0x1A` (MIT в userspace, GPL-2.0 в модуле ядра). Проприетарные и OEM-компоненты (`proprietary/`, `uwccd/lighting/oem/`) не заимствуются ни при каких условиях.

## Решение

### 1. Доменный шов `PlatformBackend` в `crates/ucc-hardware` (до `M8`)
- `uccd`, `ucc-cooling` и воркеры не должны быть жёстко привязаны к `ioctl` `/dev/tuxedo_io`.
- Вводится высокоуровневый трейт `PlatformBackend`:
  - чтение датчиков (температуры, обороты, идентификация шасси/EC);
  - управление вентиляторами (кривые CPU/GPU, `Fan Boost`, возврат `firmware auto`);
  - лимиты мощности (`PL1`/`PL2`/`PL4`, `TCC`, `cTGP`, `Dynamic Boost`, `PWUP`) и режимы/профили EC;
  - зарядка батареи (режимы и пороги заряда);
  - аппаратные переключатели (Fn Lock, Win Lock, webcam, USB sleep charging);
  - поток аппаратных WMI/горячих событий.
- На этапе `M0–M13` используется `TuxedoIoBackend` (полная совместимость с текущим стеком и откатом); для `M14` закладывается сменный `UwccBackend` с автодетектом `/dev/uwcc` vs `/dev/tuxedo_io` или явным выбором в конфиге.

### 2. Абстракция транспорта подсветки `LightingTransport` в `crates/ucc-lighting` (`M6`)
- Логика физической калибровки клавиатуры (`Enter 56`, `LShift 21`, `LCtrl 0`) и 5 анимаций Lightbar отделяется от способа доставки пакетов:
  - `SysfsLedTransport` (через `ite_8291` / `ite_8291_lb` для этапа `M6–M13`);
  - прямой USB `HidrawTransport` для `048D:600B` (клавиатура) и `048D:7001` / `048D:7000` (передняя полоса Lightbar, зоны корпуса/логотипа крышки + EC-питание `0x767`/`0x768` строго по открытому протоколу без `uwccd/lighting/oem/`) для этапа `M14`.

### 3. Собственный Rust `uwcc` на этапе `M14`
- **Модуль ядра `uwcc-rs` (`/dev/uwcc`, DKMS, GPL-2.0)**:
  - Реализуется на Rust-for-Linux (`CONFIG_RUST=y`) с `ioctl`-интерфейсом `ECRR`/`ECRW`, `SMRW`, `PWUP` и `read()/poll()` кольцевым буфером WMI-событий.
  - Регистрирует нативный интерфейс `/sys/class/hwmon/hwmonX` (`fan1_input`/`fan2_input` в реальных RPM из `0x464/0x465` и `0x46C/0x46B`, `pwm1`/`pwm2` из `0x75B/0x75C`, EC `temp*_input` без пробуждения RTX dGPU из `D3cold`), чтобы `sensors`, `btop`, `MangoHud` и `Waybar`/Noctalia видели датчики без запуска Control Center.
  - В задаче `M14.1` проверяется наличие безопасных Rust-абстракций ядра для `acpi_evaluate_*` и `wmi_driver`; если в целевом ядре часть ACPI/WMI API ещё не обёрнута, минимальные FFI-вызовы изолируются в тонком C-шиме, а вся логика драйвера, блокировки, `hwmon`, буфер событий и валидация пишутся на Rust.
- **Userspace `UwccBackend` на Rust**:
  - Переносит чистую открытую логику EC-менеджера для `0x1A` без проприетарных модулей: `RamFan 1.5` (`0xF00–0xF5C`, `CUME`/`UFME`), реальные обороты тахометра (`0x464/0x465`, `0x46C/0x46B`) через `PlatformBackend` взамен оценки `% * 60`, `SMRW`, лимит температуры CPU (`TCC`), `PWUP`, зарядку батареи, EC- и USB-переключатели (включая отключение комбинированной USB RGB+IR веб-камеры на Uniwill), трансляцию WMI-событий в `uinput`/действия демона, а также прямой `hidraw` для `048D:600B` и `048D:7001`/`048D:7000` (Lightbar, корпус, логотип крышки) с сохранением всех анимаций и физической раскладки.

### 4. Взаимоисключение и откат
- `uwcc` и `tuxedo-drivers` (`tuxedo_io`, `uniwill_wmi`, `tuxedo_keyboard`, `tuxedo_nb02_nvidia_power_ctrl`, `ite_8291`, `ite_8291_lb`) **никогда не загружаются одновременно** из-за конфликта за EC `INOU0000` и USB HID.
- Пакет `uwcc-dkms` поставляет `modprobe` blacklist модулей `tuxedo-drivers` и обеспечивает чистый откат обратно на `TuxedoIoBackend` + `tuxedo-drivers`.

## Последствия
- Базовая миграция `M0–M13` не блокируется и доводится до готовности на уже проверенном `TuxedoIoBackend`.
- После выполнения `M14` исчезает зависимость от `tuxedo-drivers-dkms` и патчей под свежие ядра, появляются `SMRW`, `TCC`, `PWUP` и нативный `RamFan 1.5`, при этом весь D-Bus API `com.uniwill.uccd` и интеграции Hyprland/Noctalia остаются неизменными.
