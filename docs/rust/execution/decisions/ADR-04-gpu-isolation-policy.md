# ADR-04: Политика мониторинга GPU и изоляция вызовов NVML (M1.8)

## Статус
Принято (Accepted)

## Контекст
На ноутбуках с гибридной графикой (Optimus: Intel/AMD iGPU + NVIDIA dGPU) дискретная видеокарта должна находиться в состоянии глубокого сна (D3cold / Runtime PM Suspended) при отсутствии активной графической нагрузки.
Прямой вызов функций NVML (`nvmlDeviceGet...`) или частый опрос через `nvidia-smi`:
1. Принудительно будит dGPU из состояния D3cold, повышая энергопотребление ноутбука на 10–25 Вт.
2. Приводит к системным зависаниям или ошибкам I/O, если вызов происходит в момент аппаратного перехода карты в сон.

## Решение
1. **Dynamic Loading (libloading / dlopen)**:
   - Библиотека `libnvidia-ml.so.1` загружается динамически в `crates/ucc-hardware`. Никаких compile-time зависимостей от CUDA/NVML SDK не допускается.
2. **PCI Runtime PM Guard**:
   - Перед любым вызовом к NVML демон проверяет статус энергосбережения dGPU в sysfs: `/sys/bus/pci/devices/<nvidia_pci_id>/power/runtime_status`.
   - Если статус равен `suspended`, вызовы NVML **не выполняются**; возвращаются кэшированные или индикативные значения «dGPU suspended», позволяя карте продолжать спать.
3. **Опциональная изоляция вызовов (Worker Process / Spawn Guard)**:
   - Для тяжелых конфигурационных вызовов (смена power limit, cTGP offset) вызовы оборачиваются в отдельный guard с таймаутом, чтобы возможный сбой проприетарного драйвера не блокировал основной event loop демона.

## Последствия
- Полное устранение нежелательного расхода батареи при мониторинге.
- Надежность демона при аппаратных сбоях драйвера NVIDIA.
