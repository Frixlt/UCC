# ADR-01: Выбор GUI Toolkit и графического стека для Frixit Control Center

## Статус
Принято — пересмотрено 2026-11-26 (заменяет первоначальный выбор `Iced`).

## Контекст
Первоначальный план предполагал переписывание 10-страничного интерфейса `ucc-gui` с C++20/Qt6 на Rust (`Iced` + `wgpu` + Canvas). Практический опыт проекта `frixit-huion` (фоновый демон на Rust + автономное окно настроек на C++20 / `Qt6::Widgets`) и аудит прототипа `crates/ucc-gui` (`iced 0.13`) выявили системные риски `Iced`:
1. **Нестабильность API и тяжёлый граф зависимостей**: `Iced` до версии `1.0` регулярно ломает API между минорными релизами, требует ~150+ транзитивных графических/шейдерных крейтов и уже показал прототипные дефекты (`GUI-01..03`).
2. **Риск пробуждения dGPU через Vulkan/wgpu**: `wgpu` при инициализации опрашивает Vulkan ICD, что на гибридной графике (Intel iGPU + NVIDIA RTX 5080) создаёт риск нежелательного пробуждения дискретной видеокарты из D3cold.
3. **Дублирование готового интерфейса**: C++ `ucc-gui` (~15 тыс. строк) уже полностью реализует все 10 разделов, включая 58-устройственную матрицу, 126-клавишную калиброванную клавиатуру, графики истории с масштабированием и настройки крышки/wakeup, и общается с демоном исключительно через контрактный D-Bus (`com.uniwill.uccd`).
4. **Отказ от KDE (`KF6`) в системе**: В текущей системе проводится очистка от пакетов KDE/Plasma; `Qt6::Widgets` (`qt6-base` + `qt6-charts`) уже установлен для утилит рабочего стола (`frixit-huion-gui`, `qt6ct`), тогда как `KF6WindowSystem`, `KF6StatusNotifierItem`, `QML/Quick` и `Qt6::Bluetooth` в окне настроек не нужны.

## Решение
1. **Гибридная архитектура по образцу `frixit-huion`**:
   - Весь фоновый стек (24/7), системный демон, аппаратные контроллеры, CLI, системный трей, агент сессии, sleep-помощники, импортеры и будущий `uwcc` (`M14`) — **100% чистый Rust** без зависимостей от Qt/GTK/C++.
   - Главное окно настроек **`ucc-gui`** — **автономный C++20 / `Qt6::Widgets` + `Qt6::Charts` D-Bus клиент**, запускаемый по требованию пользователя.
2. **Жизненный цикл «0 МБ Qt в фоне»**:
   - В фоне работают только Rust-процессы (`uccd`, `ucc-desktop-tray`, `ucc-session-agent`).
   - При закрытии окна процесс `ucc-gui` полностью завершается, освобождая память; повторное открытие происходит мгновенно по клику из Rust-трея.
3. **Удаление KDE/QML и изоляция D-Bus**:
   - Из `ucc-gui` исключаются `Qml`, `Quick`, `QuickControls2`, `Qt6::Bluetooth`, `KF6WindowSystem` и `KF6StatusNotifierItem`.
   - Активация окна на Wayland выполняется штатным путём Qt6 (`XDG_ACTIVATION_TOKEN` + `QWindow::requestActivate()`).
   - Клиентский слой `libucc-dbus` линкуется в `ucc-gui` статически; публичная разделяемая `libucc-dbus.so` больше не поставляется.
4. **Вывод `crates/ucc-gui` (`iced`)**:
   - Прототип `crates/ucc-gui` снимается с целевой поставки и исключается из `Cargo.toml` workspace на этапе `M10`.

## Последствия
- Ноль фоновых C++/Qt процессов и полное удаление зависимостей KDE (`KF6`) из пакета.
- Нативный Wayland UX (HiDPI `1.25`/`2.0`, кириллица/IME, темы `qt6ct`/Kvantum) и CPU raster-рендеринг без пробуждения NVIDIA RTX 5080.
- Сроки миграции сокращаются на 6–10 недель за счёт сохранения проверенного UI-слоя поверх Rust-демона.
