# ADR-01: Выбор GUI Toolkit и графического стека для Frixit Control Center

## Статус
Принято (Accepted)

## Контекст
Исторический C++ стек базировался на Qt6 (QtWidgets + QML + Kirigami + KDE Plasma KPackage).
Цель миграции — полный отказ от Qt и C++ в основном продукте, обеспечение легкого бинарника без раздувания зависимостей и сохранение современного десктопного UX на Wayland (Hyprland, KDE Plasma 6, GNOME) и X11.

Сравнивались кандидаты:
1. **Iced (Rust)**:
   - Плюсы: Чистый Rust, архитектура Elm/Redux (state-action-update-view), легкая кастомизация через Canvas (кривые кулеров, клавиатурные зоны, живые графики телеметрии), полная независимость от C-библиотек GUI, отличная поддержка Wayland/X11 через Winit/wgpu.
   - Минусы: Традиционно ограниченная встроенная поддержка сложных IME и системных tray-меню (решается внешним `ksni` / StatusNotifierItem).
2. **Slint (Rust/C++)**:
   - Плюсы: Декларативный UI, быстрый рендеринг.
   - Минусы: Собственный DSL-компилятор, двойная лицензия (GPLv3 / commercial), менее гибкий прямой доступ к низкоуровневым холстам.
3. **GTK4 / Libadwaita (через Rust bindings)**:
   - Плюсы: Зрелый Linux desktop toolkit.
   - Минусы: Тяжелый runtime C-библиотек (GLib, GTK4, Libadwaita), чуждый внешний вид в KDE/Hyprland без специфических тем, раздувание зависимостей дистрибутива.

## Решение
1. Для основного графического приложения (`crates/ucc-gui`) выбран **Iced** с backend `wgpu` / softbuffer.
2. Векторные и интерактивные элементы (10-страничный Fluent shell, холст настройки кривых кулеров, 3-зонная клавиатура с палитрой, временной график телеметрии с горизонтальным скроллом) реализуются через кастомные Canvas-виджеты Iced.
3. **Рендерер и энергосбережение**: Рендеринг интерфейса явно направляется на интегрированную графику (iGPU / Wayland default compositor), запрещая запросы дискретного адаптера NVIDIA через `WGPU_POWER_PREF=low_power`, предотвращая нежелательный выход dGPU из состояния D3cold.
4. **Системный трей и активация**: Трей и всплывающее меню реализуются в `crates/ucc-desktop` через протокол StatusNotifierItem (`ksni` / direct D-Bus), активируя главное окно через стандартный Wayland activation token (`xdg-activation-v1`) или X11 raise.

## Последствия
- Полный отказ от Qt6 Core/Gui/Widgets/Quick в клиентском приложении.
- Отсутствие скрытых фоновых накладных расходов C++ event loop.
- Стабильный чистый рендеринг в современных Wayland-окружениях и X11.
